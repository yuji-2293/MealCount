# 2026-10-30: 原子的な在庫加算とbatch

## 背景

購入作成時には、Purchaseを保存すると同時に、仕入れた食数をMealStockへ加える必要がある。

変更前はServiceがMealStockを読み取って在庫をJavaScriptで計算していた。変更後は、RepositoryがDBの現在値を使うUPDATE式を組み立てる。

## 実装

対象は`apps/api/src/modules/meal-stock/repositories/mealStockRepository.ts`の`buildAddPurchaseMealCountQuery`である。

```ts
const elapsedDays = sql`
  MAX(0, CAST(julianday(${today}) - julianday(${mealStock.last_calculated_date}) AS INTEGER))
`;

const differenceStock = sql`
  MAX(0, ${mealStock.current_meal_stock}
    - ${mealStock.daily_meal_count} * ${elapsedDays})
  + ${purchasedMealCount}
`;

return db
  .update(mealStock)
  .set({
    current_meal_stock: sql<number>`${differenceStock}`,
    last_calculated_date: today,
  })
  .where(eq(mealStock.id, id))
  .returning();
```

重要なのは、右辺がJavaScriptで取得済みの在庫値ではなく、`mealStock.current_meal_stock`というDBカラムであることだ。

```text
確定在庫 = max(0, DBの現在在庫 - 経過日数ぶんの消費) + 今回の仕入れ食数
```

## なぜLost Updateを防げるか

初期在庫が10のとき、5食と3食の購入作成が同時に起きた場合を考える。

```text
SQL A: current_meal_stock = current_meal_stock + 5
SQL B: current_meal_stock = current_meal_stock + 3
```

各UPDATEは実行時点のDB値を読むため、先にAが実行されればBは15を基準に更新し、最終値は18になる。

これに対して、両者がアプリケーション側で10を読んでから、15と13を保存する方式では、最終値が15または13になり、片方の更新が失われる。

## Purchase作成との組み合わせ

`purchaseRepository.createWithMealStock`は、在庫更新とPurchase INSERTをまとめている。

```ts
const purchaseQuery = purchaseRepository.buildCreateQuery(db, data);
const mealStockQuery = mealStockRepository.buildAddPurchaseMealCountQuery(
  db,
  mealStockId,
  data.purchasedMealCount
);

const [mealStockRows, purchaseRows] = await db.batch([mealStockQuery, purchaseQuery]);
```

ここでの役割は次の通りである。

| 仕組み | 担当すること |
| --- | --- |
| SQL式 | 各在庫更新でDBの最新値を使う |
| `batch` | 在庫更新とPurchase作成をまとめて実行する |
| `returning()` | 更新・作成結果をServiceへ返す |

## `batch`だけでは十分ではない理由

`batch`は複数のSQLをまとめるが、`UPDATE ... WHERE ...`が0件でもSQLエラーにはならない。

```ts
if (mealStockRows.length === 0 || purchaseRows.length === 0) {
  throw new Error('Failed to update meal stock or create purchase');
}
```

この判定はbatch後に行われるため、0件の意味を業務上どう扱うかは別途設計・テストする必要がある。`batch`は「何を失敗とみなすか」までは決めない。

## 学習の要点

- 原子的更新の本質は、SQLの右辺で対象行のカラムを使うこと
- `batch`は原子性の単位を作る仕組み、SQL式は競合で値を失わない仕組み
- この2つは補完関係にあり、同じ意味ではない
