### 基本フロー
```10日の期間で1回ごとの買い物内容を分類記録する
食材を買う
↓
在庫として持つ
↓
レシートから①~③の分類分けして、それぞれの金額と何食分あるか把握する
  1. 即日消費
  2. 計画消費
  3. 各月消費
↓
これを10日ごとに集計する
  月ごとに3フロー回る
  (重)1回ごとに記録するか、10日まとめて記録するか、どちらも選べるようにするのか？
```

```集計した内容から集計、分析できる

```

``` 集計した内容からログを出力する
- 10日間の実質1食の単価
- 必要食数（残りの月日数[30-経過日数] * 一日の食数[3]）

- １ヶ月の想定食費[円]
```

### 目的
- obsidianで使っている上記のテンプレートをアプリで自動集計、保存できるようにする

### 設計
- データとして持つもの
  1. 一度の買い物を記録する(purchase)
    - 購入日
   [入力値]
    - 買い物合計金額
    1. 即日消費
    2. 計画消費
    3. 各月消費
    - 仕入れ食数

   [算出値]
    - 実質食費合計 = (即日消費 + 計画消費)
    - その買い物の１食単価 = (実質食費合計 / 仕入れ食数)

  2. 10日ごとに集計する(カレンダーに基づいて、10日後に自動集計して、サマリにまとめる)
  [算出値]
  (10日間の消費食数[30食]を固定値とする)
   - 10日間の食費合計（買い物合計）
   - 10日間の実質食費合計
   - 買い物回数
   - 仕入れ食数
   - 現在の在庫食数 = (前回までの在庫食数 + 仕入れ食数 - 消費食数)
   - 在庫残存日数 = 現在在庫 ÷ 3
     在庫消費予定日 = 現在日 + 在庫残存日数
     -> 何日後に在庫が消費され0になる

  1. 分析（2に基づいて出力される判断指標）
   [算出値]
   (１日3食を固定値とする)
   - 10日間の1食単価 = (10日間の実質食費合計 / 10日間の食数[1日3食 * 10日 = 30食])
   - これから必要な食数 = { (1ヶ月の日数 - 現在の日数) * 1日の食数(3食) }
   - 実質必要な食数 = (これから必要な食数 - 現在の在庫食数)
   - これから必要な食費の合計 = (10日間の１食単価 * 実質必要な食数)
